Лабораторная работа №4: Файловая СУБД

Структура проекта:

- src/db/__main__.py – точка входа
- src/db/tui.py – текстовый интерфейс с выбором типа БД
- src/db/backend/database.py – абстрактный класс Database
- src/db/backend/table.py – класс Table (схема и записи)
- src/db/backend/memory.py – in-memory реализация
- src/db/backend/file.py – файловая реализация (JSON)
- src/db/backend/errors.py – пользовательские исключения
- tests/test_memory.py – тесты для MemoryDatabase
- tests/test_file_database.py – тесты для FileDatabase
- data/ – каталог для файлов таблиц (создаётся автоматически)

Реализованные функции:

- Создание таблицы с заданными колонками
- Вставка записи с проверкой соответствия схеме
- Выборка записей с фильтрацией по значениям полей
- Для файловой БД: данные сохраняются на диске и загружаются при следующем запуске
- Обработка ошибок: отсутствие таблицы, отсутствие/лишние поля, повреждённый JSON

Инструкция:

Запустить проект командой python -m src.db из корня репозитория.
При запуске выбрать тип базы данных (1 – in-memory, 2 – файловая).
Доступные команды в интерфейсе: create_table, insert, select, exit.
Пример работы:

1. create_table students id name
2. insert students id=1 name=Иван
3. select students
4. select students name=Иван

Файловая БД хранит таблицы в каталоге data/ в виде файлов students.json.

Тестирование:

Запуск тестов: python -m unittest discover tests
Покрытие основных сценариев – 100% (согласно unittest).

Отличия между in-memory и файловой реализациями:

- In-memory: данные живут только в оперативной памяти, после выхода программы теряются.
- Файловая: данные сохраняются в JSON-файлы, не теряются между запусками.
