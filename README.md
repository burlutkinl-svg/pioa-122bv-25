Структура:

Проект переработан с использованием классов (ООП). Backend – класс Table (аналог StudentTable из методички), интерфейс остался процедурным (как в прошлой работе).

- src/db/__main__.py – точка входа (вызов main())
- src/db/tui.py – процедурный пользовательский интерфейс (цикл while, обработка команд)
- src/db/backend/memory.py – класс Table для работы с одной БД
- src/db/backend/errors.py – пользовательские исключения
- tests/test_memory.py – автоматические тесты для класса Table (покрытие ~100%)

Логика работы интерфейса:

Код работает на цикле while, пока пользователь не введет 0.
Каждый ввод прогоняется по условиям: сначала проверяется, выбрана ли база данных (current_table is None).
current_table – объект класса Table, который загружает/сохраняет данные в JSON-файл.
head – имя текущей БД (только для вывода).
Файл names.txt хранит имена существующих баз данных (формат имя.json).

Реализованные функции:

- Создание/удаление баз данных, переключение между ними.
- В каждой базе данных: добавление записи (write), чтение с фильтром по ключам (read -filt ...), удаление записей (delete).
- Новая функция (доп. задание): сортировка записей по ключам при чтении – sort asc (по возрастанию), sort desc (по убыванию), sort none (отключить).

Инструкция:

Запустить проект командой python -m src.db из корня репозитория.
При первом запуске нужно будет создать новую базу данных командой create <имя>.
При создании новой БД current_table перемещается в неё.
После команды write запросят название поля и значения (через пробел).
Всё, можно работать с базами данных.
Команда check без аргументов покажет, в какой БД вы находитесь, и какие БД существуют.
Команда read без атрибута -filt выведет все поля БД (с учётом установленной сортировки).
Команда sort asc/desc/none устанавливает порядок сортировки ключей при чтении.
Выйти – 0.
